# The Internet's Worst User Journey

Finds customers who had a terrible experience even though conventional monitoring
said the system was healthy. It reconstructs their path, connects it to
deploy/trace/session signals, and produces one evidence-backed **Ghost Story**
plus a concrete fix.

> Errors are observable. Frustration usually isn't.

This build tells exactly one story: a checkout where the payment call returns
`pending`, a retry loop from deploy `c19ab` adds 6.8s with no UI feedback, the
request eventually succeeds (so monitoring stays green), and 184 customers
rage-click and leave. Codex explains the evidence chain and generates a fix:
show a pending state and cap retries.

**All telemetry is seeded, causally-locked synthetic data** shaped like
OpenTelemetry / RUM exports. There is no live Datadog/Sentry integration.

## How it works

```
data/            seeded evidence (generated by data/generate.js)
  sessions.json    240 checkout sessions; 184 match the frustration pattern
  traces.json      OpenTelemetry-style spans (all HTTP 200 / status OK)
  diff.patch       the c19ab commit that introduced the retry loop
  diagnosis.json   pre-baked Codex diagnosis + fix (offline-safe)
lib/correlate.js  the correlation engine — a deterministic join + filter, not ML
server.js         Express: /api/incident, /api/sessions, /api/traces,
                  /api/diff, /api/diagnose (SSE stream)
client/           React (Vite) UI: contrast, timeline, evidence, diagnosis, card
```

The headline number (**184**) is never hardcoded — it is the length of
`sessions.filter(matchesFrustrationPattern)`, computed at request time in
`lib/correlate.js`. Regenerate the data any time with `npm run seed`.

## Run locally

```bash
npm install            # installs server deps + seeds data (postinstall)
npm run build          # seeds data + builds the React client
npm start              # serves API + client on http://localhost:3001
```

For hot-reloading development (two terminals):

```bash
npm run dev:server     # API on :3001
npm run dev:client     # Vite dev server on :5173 (proxies /api to :3001)
```

## Deploy (one URL for judges)

The app is a single Node service that serves both the API and the built client.

**Render (free, recommended)** — push to GitHub, then either use the included
`render.yaml` blueprint (New → Blueprint) or create a Web Service manually with:
- Build command: `npm install && npm run build`
- Start command: `npm start`
- Environment: Node 22

**Docker (any host)**

```bash
docker build -t worst-user-journey .
docker run -p 3001:3001 worst-user-journey
```

**Railway / Fly / Heroku** — same two commands (`npm run build`, `npm start`);
the service reads `PORT` from the environment.

## Optional: live diagnosis

By default `/api/diagnose` streams the pre-baked response so the demo can never
break on stage. Set `ANTHROPIC_API_KEY` (and optionally `ANTHROPIC_MODEL`,
default `claude-sonnet-5`) to have the diagnosis generated live, with automatic
fallback to the pre-baked text on any error.
